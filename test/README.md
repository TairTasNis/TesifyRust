# PlayEngine

Рабочая реализация перенесена в `Backend/src/shared/playback/play_engine.rs` и подключена к приложению. Файл `test/play_engine.rs` переиспользует её для прежнего CLI, без отдельной копии алгоритма.

Папка `test/` содержит CLI для проверки того же движка, который используется в Tauri и браузерном просмотре.

## Вход и результат

- Название песни: `&str`.
- Исполнитель: `&str`.
- Необязательная длительность в секундах: `Option<u64>`.
- `find_url()` возвращает `Result<String, PlayEngineError>` с обычной ссылкой YouTube.
- `find()` возвращает ссылку, название найденного видео, канал, его длительность и разницу с запрошенной длительностью.

```rust
use play_engine::PlayEngine;

let engine = PlayEngine::new();
let url = engine.find_url("Blinding Lights", "The Weeknd", Some(200))?;
let without_duration = engine.find_url("Группа крови", "Кино", None)?;
```

Методы блокирующие; приложение вызывает их через `tauri::async_runtime::spawn_blocking`.

## Запуск из корня проекта

```powershell
cargo run --manifest-path test/Cargo.toml -- "Blinding Lights" "The Weeknd" 200
cargo run --manifest-path test/Cargo.toml -- "Группа крови" "Кино"
cargo run --manifest-path test/Cargo.toml -- "Blinding Lights" "The Weeknd" 200 --details
cargo test --manifest-path test/Cargo.toml
```

Нужны Rust, доступ к YouTube и установленный [yt-dlp](https://github.com/yt-dlp/yt-dlp). Поиск использует `ytsearch`, `--flat-playlist` и JSON-метаданные с длительностью. API-ключ не требуется. Видео и аудио не скачиваются. Если инструмент находится не в PATH, укажите путь:

```powershell
$env:YT_DLP_PATH = 'C:\path\to\yt-dlp.exe'
```

## Подбор

1. Видеопоиск и поиск аудиозаписей в YouTube Music запускаются параллельно. Число результатов каждой выборки можно настроить методом `with_search_limit()` в пределах 1–50, по умолчанию 40.
2. До шести подходящих по названию записей YouTube Music проверяются по метаданным. Одновременно проверяются не более двух записей. Сначала используется запрос только нужных для подбора метаданных, затем при необходимости полный запрос.
3. Запасные видеозапросы учитывают варианты имени и названия. Оставшиеся процессы останавливаются, когда найдено подтверждённое совпадение с отклонением до 1,5 секунды. Все поисковые этапы делят общий бюджет 45 секунд.
4. Проверка названия, исполнителя и языка версии. `Russian Ver.` и `на русском` сопоставляются; незапрошенные ремиксы, live, караоке и каверы другого исполнителя исключаются. Кавер самого запрошенного исполнителя допускается по его каналу или явной подписи `Cover by <исполнитель>`.
5. Среди проверенных записей выбирается ближайшая длительность. В пределах 1,5 секунды приоритет получают подтверждённые записи, например Topic и official audio. Tesify использует миллисекунды из каталога, CLI принимает секунды.

Ближайшая длительность определяется среди найденных и прошедших фильтры результатов, а не среди всех видео YouTube. Поиск по метаданным является эвристикой: он не анализирует сам звук и не гарантирует доступность воспроизведения. При заданной длительности результаты без неё пропускаются. Процессы поиска завершаются при превышении общего таймаута, который можно изменить через `with_timeout()`. Подготовка аудиопотока имеет отдельный таймаут.

Проверка случая `Monitoring - Russian Ver.` / `Sati Akura` / `176`: музыкальный поиск возвращает `BF7hRVab23w`, `Monitoring (Russian Ver.)`, 177 секунд. Видеопоиск ранее показывал клип на 218 секунд и пропускал студийную запись.
