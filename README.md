# Tesify

Музыкальное приложение на React + TypeScript + Vite и Tauri v3.

## Структура

- `Frontend/src/pages/` — страницы Home, Search, Library, Playlist и About. Код каждой страницы хранится в собственной папке.
- `Frontend/src/app/` — сборка приложения и навигация.
- `Frontend/src/shared/` — общая оболочка, элементы интерфейса, стили и логотип.
- `Backend/` — Rust-приложение и конфигурация Tauri.
- `Backend/src/pages/` — серверные модули About, Library и Playlist.
- `instructions.md` — правила организации папок для дальнейшей разработки.

## Установка зависимостей

Требуется Node.js 20.19+ или 22.12+ и npm. Для настольного приложения также нужны Rust 1.95+, Visual Studio C++ Build Tools и Microsoft Edge WebView2.

```powershell
npm run install:frontend
```

Все команды в этом документе запускаются из корня проекта.

## Настольное приложение

```powershell
npm run desktop:dev
```

Команда запускает фронтенд на порту 1420 и настоящее окно Windows без системной панели заголовка. Верхнюю свободную область можно перетаскивать, в том числе на странице «О программе». Кнопки сворачивания, разворачивания и закрытия управляют нативным окном. При изменении размера состояние кнопки разворачивания обновляется автоматически.

Используются зафиксированные версии Tauri 3.0.0-alpha.5, Wry runtime 3.0.0-alpha.5, CLI 3.0.0-alpha.5 и JavaScript API 3.0.0-alpha.3. Это предварительный выпуск Tauri v3; [официальные релизы](https://github.com/tauri-apps/tauri/releases).

## Просмотр в браузере

```powershell
npm run dev
```

Команда запускает Rust-сервис на `127.0.0.1:17830` и Vite на `127.0.0.1:5173`. Браузерный интерфейс использует те же сохранённые плейлисты и тот же импорт, что и Tauri. В браузере сохраняется имитация кнопок окна. При первом запуске потребуется время для компиляции Rust. Остановить оба процесса можно сочетанием Ctrl+C.

## Плейлисты и обложки

Во вкладке «Библиотека» можно создать плейлист с произвольным названием, описанием и обложкой. На странице плейлиста доступны список треков, редактирование и удаление. Карточки имеют одинаковые квадратные обложки и выравниваются по верхнему краю независимо от описания.

Обложки PNG, JPG или WebP до 8 МБ загружаются в imgbb через Rust. Ключ находится только в корневом `.env`:

```dotenv
IMGBB_API_KEY=your_key_here
```

`.env` исключён из Git и не включается в frontend или установщик. При переносе установленного приложения на другой компьютер `.env` можно разместить рядом с исполняемым файлом или в папке данных приложения. Также поддерживается переменная `TESIFY_ENV_FILE` с путём к конфигурации. После изменения ключа приложение нужно перезапустить.

Данные постоянно хранятся в `library.json` в папке данных Tesify (`%APPDATA%/app.tesify.desktop` в Windows). Путь можно изменить через `TESIFY_DATA_DIR`. Запись выполняется атомарно, с блокировкой от одновременных изменений браузерной и настольной версий.

## Импорт Spotify

В плейлисте открыть «Редактировать» и нажать «Импортировать плейлист» внизу слева. Текущие изменения названия, описания и обложки сохраняются перед переходом к импорту. Затем выбрать Spotify и вставить полную ссылку на публичный плейлист `https://open.spotify.com/playlist/…`. Закрытие окна импорта возвращает к редактированию; после успешного импорта открывается обновлённый список треков.

Импорт адаптирован из вашего проекта `D:/Python/Tesify/src-tauri/src/backend.rs`. Сохранены гостевой доступ, запрос `fetchPlaylist`, загрузка всех страниц и разбор полей. Треки добавляются в существующий плейлист; его название и описание сохраняются. Если своей обложки нет, используется обложка исходного плейлиста.

У каждого трека показываются название, исполнители, обложка, длительность и дата добавления из Spotify. Если исходная дата отсутствует, показывается дата импорта. Повторные треки пропускаются. Недоступные и неподдерживаемые записи также учитываются в результате backend. Плашка результата импорта в интерфейсе не показывается. При ошибке одной из страниц частичный импорт не сохраняется. Приватные плейлисты без гостевого доступа не поддерживаются.

## Воспроизведение музыки

Нажатие на трек запускает рабочий `Backend/src/shared/playback/play_engine.rs`: он подбирает YouTube-запись по названию, основному исполнителю и ближайшей длительности, затем получает аудиопоток. Проверенный официальный [yt-dlp](https://github.com/yt-dlp/yt-dlp) хранится в `Backend/tools` и включён в установщик; контрольная сумма и сведения о лицензиях записаны рядом. Для воспроизведения также нужен [Node.js 22+ с поддержкой EJS](https://github.com/yt-dlp/yt-dlp/wiki/EJS). Пути инструментов можно переопределить в `.env` через `YT_DLP_PATH` и `YT_DLP_JS_RUNTIME`. FFmpeg для потокового воспроизведения не нужен.

Миниплеер сохраняется при переходе между страницами. Доступны пауза, продолжение, предыдущий и следующий трек, автоматический переход после окончания, громкость и отключение звука. Время «сыграло / всего» расположено под тремя кнопками управления на всех размерах окна. Прогресс заполняет фон миниплеера: нажмите или перетащите по свободной области для перемотки. В фокусе плеера стрелки меняют позицию на пять секунд, Home/End переходят в начало/конец. Пробел и системные медиаклавиши также поддерживаются. Громкость запоминается на устройстве; её слайдер имеет собственную дорожку, заливку и бегунок.

Rust передаёт аудио через локальный сервис с поддержкой диапазонов байтов и обновлением истёкшего адреса источника. В папке данных приложения `audio-intros-v1` сохраняется начало записи примерно на пять секунд с запасом для контейнера и его индекс в конце файла. Полный трек не сохраняется. Кэш ограничен 64 МБ и 128 записями, старые записи вытесняются автоматически. Он общий для браузерной и настольной версии и сохраняется после перезапуска. Подписанные временные URL в него не записываются: при повторном запуске начало отдаётся локально, а адрес продолжения обновляется параллельно. При изменении формата или размера записи устаревший фрагмент сбрасывается.

После достижения 50% текущего трека начинается однократная подготовка следующего: подбор записи, получение адреса и сохранение начала. Готовый результат используется при переключении без повторного поиска. Ошибка предварительной загрузки не прерывает текущую музыку; следующий трек при необходимости готовится обычным способом. Ошибки воспроизведения показываются внутри плеера с возможностью повторить попытку.

Поиск текста запускается при выборе трека одновременно с подготовкой аудио. Найденный текст и тайминги сохраняются в `lyrics-v1` рядом с `audio-intros-v1`. При запуске через `npx tauri dev` на Windows обе папки находятся в `%APPDATA%/app.tesify.desktop`. Переменная `TESIFY_DATA_DIR` переопределяет этот путь. Кэш текста ограничен 32 МБ и 128 записями.

## Проверка и сборка

```powershell
npm run build
npm run desktop:check
npm run desktop:build
```

`desktop:build` создаёт приложение и установщик Windows. Результаты находятся в `Backend/target/release/` и `Backend/target/release/bundle/nsis/`. `desktop:check` проверяет Rust-код с зафиксированными зависимостями из `Backend/Cargo.lock`.

## Интерфейс

Сохранены белая рабочая область, скруглённое окно, боковая панель и блок управления окном из макета. Используется оригинальный прозрачный логотип в разрешении 2048 × 2048; его форма и цвета не перерисованы.

В боковой панели доступны главная, поиск, библиотека и настройки. В разделе «Основное» можно выбрать русский, английский или казахский язык и включить тёмную тему. Эти настройки сохраняются между запусками WebView.

Нажатие на логотип открывает страницу «О программе» (`#about`) с названием Tesify и версией 26.11 dev 02. В настольном приложении сведения о версии поступают из Rust-команды `get_app_info`. Для названия используется Michroma, для версии — Manrope. Шрифты включены в приложение и не требуют подключения к Google Fonts. Стрелка назад или Escape возвращают в предыдущий раздел; прямое открытие страницы и перезагрузка также поддерживаются.
