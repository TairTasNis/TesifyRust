# Правила организации проекта Tesify

## Основная схема

В корне проекта находятся `Frontend/`, `Backend/` и этот файл `instructions.md`.
Код нужно организовывать по страницам: у каждой страницы своя папка с её названием.
Всё, что относится только к этой странице, хранится внутри её папки.

## Frontend

```text
Frontend/src/
  app/                  # Сборка приложения, маршруты и общие настройки приложения
  pages/
    Home/               # Главная
    Search/             # Поиск
    Library/            # Музыка и плейлисты
    Settings/           # Настройки интерфейса и память
    Playlist/           # Страница плейлиста, треки и импорт
    About/              # О программе
    Lyrics/             # Синхронный текст, анимация строк и фон по обложке
    Artist/             # Профиль исполнителя Spotify и дискография
    Album/              # Альбом Spotify и его треки
    SpotifyPlaylist/    # Просмотр публичного плейлиста Spotify
  shared/
    assets/             # Общие изображения и логотип
    layout/             # Общая оболочка окна, боковая панель и кнопки окна
    ui/                 # Переиспользуемые элементы интерфейса
    styles/             # Только общие стили и сброс
    playlists/          # Типы и форма плейлиста, используемые на нескольких страницах
    playback/           # Общее воспроизведение, очередь и MiniPlayer
    preferences/        # Настройки интерфейса и переводы
    catalog/            # Модели, карточки, таблицы и общий вид коллекций каталога
```

- Компонент страницы, её стили, запросы, типы, вспомогательные функции и внутренние компоненты находятся в папке этой страницы.
- Для новой страницы сначала создаётся `Frontend/src/pages/<НазваниеСтраницы>/`.
- Стили страницы не складываются в один общий файл со стилями других страниц.
- В `shared/` выносится только код, который используется несколькими страницами или всей оболочкой приложения. У самостоятельного общего компонента должна быть своя папка.
- В `app/` находится только сборка приложения и навигация, а не реализация всех страниц сразу.
- `main.tsx` остаётся входной точкой в `src/`.
- Общие параметры движения находятся в `shared/styles/global.css`, определение ввода с клавиатуры — в `shared/lib/motion.ts`, музыкальные индикаторы загрузки — в `shared/ui/MusicLoader/`. Анимации конкретной страницы остаются в её стилях. Учитывать `prefers-reduced-motion`, не задерживать запросы и воспроизведение ради анимации.

## Backend

```text
Backend/
  Cargo.toml
  tauri.conf.json
  capabilities/
  icons/
  src/
    main.rs             # Запуск настольного приложения
    lib.rs              # Регистрация модулей и команд Tauri
    pages/
      about/            # Логика страницы About
        mod.rs
        commands.rs
        models.rs
      library/          # Создание и список плейлистов, загрузка обложек
      lyrics/           # Поиск по источникам, разбор LRC/TTML/YRC/KRC и кэш текста
      playlist/         # Данные плейлиста и импорт Spotify
      search/           # Гостевой поиск Spotify
      settings/         # Использование памяти и очистка превью песен
      artist/           # Исполнитель и страницы дискографии
      album/            # Альбом Spotify
      spotify_playlist/ # Публичный плейлист Spotify
    shared/
      playlists/        # Общие модели и постоянное хранилище
      playback/         # Рабочий PlayEngine, подготовка записи и поток аудио
      spotify/          # Общий гостевой клиент, модели, преобразование и описание API
      config.rs         # Чтение настроек из .env
    preview/            # Локальный HTTP-мост для браузерного просмотра
```

- Логика каждой страницы находится в `Backend/src/pages/<название_страницы>/`. Имена Rust-модулей записываются в `snake_case`, например `about` для страницы `About`.
- Команды Tauri, модели, сервисы и работа с данными конкретной страницы хранятся внутри её папки.
- Общая серверная логика выносится в `Backend/src/shared/`, когда в ней появляется реальная необходимость.
- `lib.rs` собирает приложение и регистрирует команды; бизнес-логика страниц в нём не пишется.
- Папка серверного модуля создаётся, когда у соответствующей страницы появляется серверная логика. Не нужно добавлять пустые команды ради структуры.

## Для последующих изменений

Ключи внешних сервисов хранить в корневом `.env`, который исключён из Git. В `.env.example` оставлять только названия переменных. Не добавлять ключи в frontend, переменные `VITE_*`, исходный код, установщик или сообщения об ошибках. Загрузка обложек imgbb выполняется в Rust. Браузерный просмотр использует тот же Rust-код через локальный сервис; отдельную систему импорта во frontend не создавать.

Импорт Spotify перенесён из `D:/Python/Tesify/src-tauri/src/backend.rs`; поддерживать эту реализацию в `Backend/src/pages/playlist/spotify.rs`, сохраняя постраничную загрузку и отображение метаданных. Не заменять импорт фиктивными треками.

Гостевой поиск и страницы каталога используют общий Rust-клиент `Backend/src/shared/spotify/`, основанный на прежнем `D:/Python/Tesify/src-tauri/src/search.rs`. Наблюдаемые запросы и ответы описаны в `Backend/src/shared/spotify/README.md`. Токены гостя хранятся только в памяти Backend. Месячные слушатели, обложки, биографии и счётчики берутся из реального ответа Spotify; пропуски не заполнять придуманными данными. Постраничную загрузку сохранять во всех категориях. Для воспроизведения каталога frontend передаёт только ID уже полученного трека; произвольные метаданные/аудиоадреса не принимать.

Общая логика воспроизведения находится в `Backend/src/shared/playback/`, рабочий файл PlayEngine — `play_engine.rs`. Движок использует видеопоиск, запасной поиск YouTube Music с проверкой метаданных и варианты названия; сохранять общий таймаут, проверку исполнителя и фильтры версий. Подготовка трека принимает идентификаторы существующего плейлиста и трека; произвольные адреса для проксирования frontend не передаёт. Аудиосервис слушает только loopback и поддерживает запросы диапазонов для перемотки. Глобальная очередь и миниплеер находятся в `Frontend/src/shared/playback/`, чтобы музыка не прерывалась при смене страницы. Общий индикатор играющего трека находится в `Frontend/src/shared/ui/PlaybackIndicator/`; движение включать только при воспроизведении без загрузки/ошибки, учитывать паузу и уменьшенное движение.

Сохранение начала записи и ограничение дискового кэша реализованы в `Backend/src/shared/playback/intro_cache.rs`; данные находятся в `audio-intros-v1` внутри папки данных приложения. Хранить только начало и индекс контейнера, ограничивать общий размер и переиспользовать кэш между браузером и Tauri. Предварительную загрузку следующего трека после 50% запускать из общего PlaybackProvider, не из отдельных страниц. Отказы фоновой подготовки не должны прерывать текущий трек.

Отдельные экспериментальные Rust-модули по явному запросу пользователя могут находиться в корневой папке `test/`. Их не подключать к основному приложению без отдельной задачи. По просьбе пользователя PlayEngine теперь подключён к приложению: `test/play_engine.rs` переиспользует рабочую реализацию из Backend, а CLI-пример и Cargo-проект сохранены. Логику поиска в двух местах не дублировать.

Сохранять эту схему при добавлении новых страниц и функций. Если функция относится к определённой странице, сначала искать её папку и дорабатывать код там. Общие элементы не дублировать по страницам. При изменении принятой структуры обновлять этот файл.

Текст песен находится в `Frontend/src/pages/Lyrics/` и `Backend/src/pages/lyrics/`. Поиск принимает только идентификаторы уже известного трека, использует метаданные из Backend и выполняется через тот же Rust-сервис в Tauri и браузерном просмотре. Пословные тайминги имеют приоритет над построчными; не создавать искусственные тайминги слов из длины строки. Перемотка и подсветка опираются на часы общего аудиоплеера. Известные серверы LyricsPlus перебираются с ограничением времени; дополнительные адреса и ключ BetterLyrics настраиваются только через серверный `.env`. Описание источников и проверки находятся в `Backend/src/pages/lyrics/README.md`.
